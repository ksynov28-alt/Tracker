# Lucro — трекер задач

Внутренняя система управления задачами компании Lucro: распределение задач между сотрудниками, контроль сроков, проверка результатов руководителем, комментарии, вложения, уведомления и статистика.

Приложение рассчитано на фиксированное десктопное разрешение (от 1280 px) и не адаптируется под мобильные устройства — это соответствует требованиям ТЗ.

## Стек

- **Сервер:** Node.js 26, Express 5, встроенный `node:sqlite` (`DatabaseSync`), `multer` для загрузки файлов.
- **Клиент:** React 19, TypeScript, Vite 7, React Router 7.
- **Стили:** обычный CSS, разбитый по модулям; шрифт Inter, иконки `lucide-react`, даты `date-fns` (локаль `ru`).
- **Авторизация:** серверные сессии в httpOnly-cookie `lucro_session`, пароли — `scrypt`.
- **Хранение:** SQLite-база `data/lucro.db`, файлы — в `data/uploads`.

## Быстрый старт

Требуется Node.js 24+ (проект проверен на Node.js 26.13.0) и npm.

```bash
npm install
npm run seed        # демо-данные: 11 пользователей и 13 задач
npm run build       # сборка клиента в dist/
npm start           # http://localhost:3001
```

Для разработки:

```bash
npm run dev         # сервер на :3001 + Vite на :5173 с прокси /api
```

Полезные команды:

| Команда | Назначение |
| --- | --- |
| `npm start` | Запуск Express-сервера и раздача собранного клиента из `dist/` |
| `npm run dev` | Режим разработки: сервер и Vite одновременно |
| `npm run build` | Сборка клиента |
| `npm run typecheck` | Проверка TypeScript |
| `npm run seed` | Полный сброс базы и создание демо-данных |
| `npm run seed:demo` | Дозаполнение пустой базы демо-данными |

Порт сервера можно изменить переменной окружения `PORT` (по умолчанию `3001`).

## Роли и права

Права проверяются на сервере для каждого запроса, а клиент лишь скрывает недоступные действия.

| Возможность | Администратор | Руководитель компании | Руководитель | Сотрудник |
| --- | :---: | :---: | :---: | :---: |
| Просмотр задач | да | да | да | да |
| Создание, редактирование, удаление задач | да | да | да | — |
| Назначение ответственных, сроков и приоритета | да | да | да | — |
| Начало работы и отправка на проверку | — | — | — | ответственные |
| Принятие задачи и возврат на доработку | да | да | да | — |
| Отмена задачи с причиной | да | да | да | — |
| Комментарии | да | да | да | да |
| Загрузка вложений | да | да | да | ответственные |
| Статистика | да | да | да | — |
| Управление пользователями и настройками | да | — | — | — |

Дополнительно:

- самостоятельная регистрация создаёт заявку со статусом «на подтверждении»;
- одобрить или отклонить заявку, сменить роль и сбросить пароль может только администратор;
- самостоятельного восстановления пароля нет — пароль выдаёт администратор;
- редактирование задачи меняет только текст и инструкции: ответственные, приоритет и крайний срок фиксируются при создании;
- удалить задачу может руководитель, отмена сохраняет задачу в системе с причиной.

## Жизненный цикл задачи

Статусы: **Новая → В работе → На проверке → Завершена**, а также **Просрочена** и **Отменена**.

- Начать работу может любой ответственный; после этого задача переходит в «В работе».
- Отправка на проверку одним из ответственных переводит всю коллективную задачу в «На проверке».
- Руководитель принимает задачу (всем ответственным уходит уведомление) или возвращает на доработку — обязательно с комментарием, статус снова «В работе».
- Отмена требует причины и не удаляет задачу.
- Фоновая проверка раз в 30 секунд переводит просроченные задачи в «Просрочена». Если после этого работу возобновили, задача возвращается в «В работе» и получает суточное окно, в течение которого не помечается просроченной повторно.
- За 24 часа до срока ответственные получают напоминание; о просрочке уведомляются руководители.
- Уведомления приходят всплывающими сообщениями (toast) без отдельного центра уведомлений.

## Возможности интерфейса

- Список задач с поиском по названию, фильтрами по ответственному, статусу и срокам, сортировкой по приоритету, сроку и дате создания.
- Календарь в режимах день / неделя / месяц.
- Kanban-доска с шестью колонками по статусам.
- Карточка задачи: описание, инструкции, ответственные, сроки, вложения, комментарии, действия по статусу.
- Комментарии с автоматическим превращением ссылок в кликабельные; редактировать и удалять можно только свои.
- Вложения: несколько файлов, до 10 МБ каждый, скачивание и удаление.
- Статистика для руководителей: сводка по статусам, нагрузке и результатам сотрудников.
- Администрирование: заявки, роли, сброс паролей, настройки компании и регистрации.

```
server/
  index.js            точка входа Express
  config.js           пути, лимиты, роли, статусы, настройки
  db.js               схема SQLite и настройки
  auth.js             пароли, сессии, проверки ролей
  notify.js           создание уведомлений
  scheduler.js        просрочки и напоминания за 24 часа
  upload.js           multer, лимиты и имена файлов
  seed.js             демо-данные
  routes/             auth, tasks, admin, stats, files, notifications, public
client/src/
  pages/              вход, регистрация, задачи, статистика, пользователи, настройки
  components/         карточка задачи, форма, фильтры, представления, UI-компоненты
  context/            авторизация и toast-уведомления
  styles/             CSS-модули
  api.ts              клиент API
data/
  lucro.db            база SQLite (создаётся автоматически)
  uploads/            загруженные файлы
dist/                 собранный клиент
```

## API (кратко)

- `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`, `POST /api/auth/register`
- `GET /api/tasks`, `GET /api/tasks/:id`, `POST /api/tasks`, `PUT /api/tasks/:id`, `DELETE /api/tasks/:id`
- `POST /api/tasks/:id/actions` — `start`, `submit`, `accept`, `return`, `cancel`
- `GET/POST /api/tasks/:id/comments`, `PUT/DELETE /api/tasks/:id/comments/:commentId`
- `POST /api/tasks/:id/attachments`, `DELETE /api/tasks/:id/attachments/:attachmentId`, `GET /api/attachments/:id/download`
- `GET /api/notifications`
- `GET /api/users`, `GET /api/public/config`
- `GET /api/stats`
- `/api/admin/*` — пользователи, заявки, роли, сброс пароля, настройки

## Данные и резервное копирование

Все данные находятся в каталоге `data/`. Для резервной копии достаточно остановить сервер и скопировать `data/lucro.db` и `data/uploads/`. Команда `npm run seed` полностью очищает базу и пересоздаёт демо-данные — не используйте её на рабочих данных.
